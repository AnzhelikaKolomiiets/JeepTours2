# Lab 1 та Lab 2. Налаштування середовища, концепція та базова реалізація мобільного AI-застосунку «JeepTours»


# Lab 1. Налаштування середовища та концепція мобільного додатку

## 1. Середовище розробки
Встановлено Android Studio, створено проєкт з шаблону Empty Activity, додаток запущено на емуляторі Android (Pixel).

## 2. Індустрія
Туризм, активний відпочинок та екстремальні подорожі (Off-road джип-тури).

## 3. Ідея додатку
* **Назва:** JeepTours — генератор джип-турів з AI-розкладом та вибором складності.
* **Цільова аудиторія:** Туристи, активна молодь, сім'ї та любителі екстриму віком 18-60 років.
* **Ключова проблема:** Складність у плануванні індивідуального маршруту поїздки, невизначеність графіку та відсутність швидкої адаптації під рівень підготовки та вподобання туриста.
* **Унікальна цінність:** Формування багатоваріантних персоналізованих маршрутів джип-турів із деталізованим погодинним графіком дій, підбором підходящого класу позашляховика та застереженнями з безпеки за допомогою ШІ.
* **Порівняння з аналогами:** TripAdvisor, AllTrails, Komoot. Аналоги надають лише статичні готові маршрути без динамічного розрахунку часу під індивідуальні вподобання, без адаптивного вибору класу авто та без урахування рівня складності (EASY / MEDIUM / HARD) у реальному часі.
* **MVP-скоуп:**
    * **Входить у MVP:** введення параметрів поїздки (тривалість у годинах, рівень складності, персональні вподобання); вибір варіантів турів з динамічним перемиканням; відображення рекомендованого автомобіля; погодинний графік дій; застереження з безпеки; відображення станів UI (Idle, Loading, Success, Error).
    * **Не входить у MVP (відкладено на V1-V2):** бронування авто та гіда; інтерактивна GPS-карта з офлайн-навігацією; відгуки та рейтинги; оцінка вартості туру в грн/USD; соціальні функції (поділитися маршрутом).

## 4. Архітектура

### Етапи розвитку
| Рівень | Що входить |
| :--- | :--- |
| **POC** | Форма введення тривалості, кнопка генерації, один запит до API з виведенням тексту маршруту. |
| **MVP** | Інтерактивний вибір складності, багатоваріантні маршрути (Варіант 1 / Варіант 2), погодинний розклад, підбір автомобіля, застереження з безпеки, обробка помилок мережі. |
| **V1** | Інтеграція з GPS-картами, вибір кількості пасажирів, розрахунок орієнтовної вартості, збереження обраних турів у фаворити. |
| **V2** | Онлайн-бронування, кабінет гіда, офлайн-карти, відгуки та соціальний шеринг. |

*За межами курсу: V1 і V2.*

### User stories для MVP
1. Як користувач, я хочу вказати тривалість туру в годинах, щоб розпланувати свій час.
2. Як користувач, я хочу обрати рівень складності (EASY, MEDIUM, HARD), щоб поїздка відповідала моєму досвіду та комфорту.
3. Як користувач, я хочу ввести свої вподобання (наприклад, «водоспади та оглядові майданчики»), щоб отримати релевантний маршрут.
4. Як користувач, я хочу бачити кілька варіантів туру (Варіант 1 / Варіант 2) та легко перемикатися між ними.
5. Як користувач, я хочу бачити детальний погодинний графік дій для обраного варіанту.
6. Як користувач, я хочу бачити рекомендований тип автомобіля та поради з безпеки для обраного рівня складності.

### Компоненти системи
| Шар | Технологія | Обґрунтування |
| :--- | :--- | :--- |
| **Mobile** | Kotlin + Jetpack Compose | Сучасний Android-стандарт declarative UI |
| **Асинхронність & Мережа** | Coroutines, StateFlow, Retrofit2, Gson | Надійний асинхронний зв'язок із backend API |
| **Backend** | Python + FastAPI + Uvicorn | Швидка розробка, асинхронність, Pydantic-валідація |
| **AI-шар / Логіка** | Dynamic Rule Engine / AI Prompting | Генерація варіативних маршрутів та графіків залежно від вхідних параметрів |

### Потік даних
1. Користувач вводить тривалість, обирає складність (EASY / MEDIUM / HARD) та вказує вподобання в Compose UI.
2. `TourViewModel` збирає дані та викликає `TourRepository`.
3. `TourRepository` надсилає HTTP POST-запит на `/api/v1/tours/generate`.
4. FastAPI backend отримує та валідує JSON-запит через Pydantic.
5. AI/Бекенд-логіка аналізує параметри, обирає клас авто, формує застереження з безпеки та генерує масив з кількох варіантів маршрутів з їх погодинними розкладами.
6. Мобільний додаток отримує JSON-відповідь, оновлює `TourUiState.Success` та відображає картку результату з кнопками перемикання варіантів.

## 5. Вимоги

### Функціональні вимоги
* **FR1.** Система повинна дозволяти ввести тривалість туру в годинах (від 1 до 24).
* **FR2.** Система повинна дозволяти обрати один із трьох рівнів складності: EASY, MEDIUM, HARD.
* **FR3.** Система повинна дозволяти вказати довільні текстові вподобання користувача.
* **FR4.** Система повинна генерувати та повертати щонайменше 2 варіанти маршрутів.
* **FR5.** Система повинна показувати погодинний графік дій для кожного варіанту.
* **FR6.** Система повинна підбирати тип автомобіля залежно від рівня складності.
* **FR7.** Система повинна надавати спеціалізовані застереження з безпеки.
* **FR8.** Система повинна дозволяти інтерактивно перемикатися між варіантами маршрутів без повторного запиту.

### Нефункціональні вимоги
* **Продуктивність:** Час відповіді сервера не повинен перевищувати 3 секунд.
* **Безпека:** Відсутність передачі конфіденційних персональних даних; чітке розділення UI та бекенд-логіки.
* **Надійність:** Індикація стану завантаження (`Loading`) та зрозуміле повідомлення про помилку у разі відсутності зв'язку з сервером (`Error`).
* **Пристрої:** Android 8.0+ (API 26+).

# Lab 2. Базова реалізація мобільного AI-застосунку «JeepTours»

Працюючий MVP: Android (Kotlin + Jetpack Compose) → HTTP API → backend (Python + FastAPI) → AI/Бекенд-компонент → результат у UI зі станами Idle / Loading / Success / Error.

## 1. Сценарій (Task 1)
> *«Як турист (18-60 років), я хочу ввести тривалість поїздки, обрати складність та вказати свої вподобання, щоб отримати кілька варіантів персоналізованих джип-турів із погодинним розкладом та порадами з безпеки»*.

Сценарій покриває всі шари системи: UI (Compose) → Мережа (Retrofit) → Backend (FastAPI + Pydantic) → AI/Бекенд-генерація → UI (StateFlow).

## 2. Архітектура та дані (Task 2)

### Вхідні дані POST /api/v1/tours/generate
| Поле | Тип | Обов'язкове | Обмеження / Опис |
| :--- | :--- | :--- | :--- |
| `duration_hours` | int | Так | Від 1 до 24 годин |
| `difficulty` | string | Так | `EASY`, `MEDIUM`, `HARD` |
| `preferences` | string | Ні | Текст до 200 символів |

### Успішна відповідь (200 OK)
Повертається об'єкт `TourResponse`, що містить:
* `tour_title` (string) — заголовок туру;
* `estimated_time` (string) — оціночний час;
* `recommended_vehicle` (string) — рекомендована машина під складність;
* `routes` (array of RouteOption) — масив варіантів з `id`, `name`, `description`, `schedule` (масив строкових елементів часу);
* `safety_tips` (string) — поради з безпеки.

## 4. Запуск backend

Потрібен Python 3.10+. З кореня репозиторію (Windows, CMD / PowerShell):
```bash
cd backend
cd /d D:\Jeep\backend
venv\Scripts\activate
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```
* **Перевірка статусу:** `http://localhost:8000/health` → `{"status":"ok"}`
* **Swagger UI:** `http://localhost:8000/docs`

## 5. Запуск mobile

1. Відкрити проєкт `JeepTours2` в Android Studio.
2. Переконатися у наявності дозволів у `AndroidManifest.xml`:
   ```xml
   <uses-permission android:name="android.permission.INTERNET" />
   <application android:usesCleartextTraffic="true" ...>
   ```
3. Конфігурація адреси сервера в `TourApiService.kt`:
    * **Емулятор:** `http://10.0.2.2:8000/`
    * **Фізичний пристрій:** `http://<IP_вашого_ПК>:8000/`
4. Запустити додаток на емуляторі натисканням **Run 'app'**.

У ході виконання лабораторних робіт №1 та №2 було успішно розроблено та протестовано мінімальний працездатний продукт (MVP) мобільного AI-застосунку «JeepTours».
